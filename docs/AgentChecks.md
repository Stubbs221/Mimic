# Сборки и выбранные тесты через агента

Строгий цикл доступен в Mimic 1.5.0 с `get_agent_state.capabilities.agentWorkflowVersion = 2`; совместимый workflow v1 сохраняется. Предыдущим версиям Mimic для этих инструментов требуется обновление. Агент выбирает проверки и исправляет код; Mimic выполняет проверки в своей общей очереди. Запуски видны в существующей истории приложения и панели.

## Подключение

В Codex используйте существующий плагин Mimic. После обновления переподключите плагин, если хост сохранил прежний каталог инструментов. Панель необязательна: `bind_project` привязывает текущий чат к его абсолютному Git checkout.

В Claude Code подключите установленный подписанный helper, подставив фактический путь приложения:

```sh
claude mcp add --scope user --transport stdio mimic -- /Applications/Mimic.app/Contents/Helpers/MimicMCP
```

Команда меняет пользовательскую конфигурацию Claude Code; выполняйте её при подключении Mimic. Node.js и веб-сервер не нужны. Профиль, Xcode и Apple target настраиваются в самом Mimic. Claude Code получает инструменты; встроенный интерфейс панели рассчитан на Codex.

Клиент без идентификатора чата получает отдельную привязку на время MCP-соединения. После переподключения повторите `bind_project`. Выбор проекта десктопа не подставляется автоматически.

## Ручной запуск

Блок «Сборки и тесты» запускает целый тестовый таргет из поля «Набор тестов». Доступные таргеты читаются из схемы и её тестовых планов без перечисления методов и подготовительной сборки. По умолчанию выбирается первый включённый таргет стандартного плана. При смене схемы неподходящий выбор заменяется доступным; если таргетов нет, запуск недоступен.

Успех и подтверждённая отмена возвращают компактную плашку в исходное состояние. Ошибка сохраняется до открытия результата этого прогона, в том числе после перезапуска. Просмотр в macOS или Codex снимает отметку в обеих поверхностях. Неизвестный результат продолжает блокировать повтор, даже после просмотра. Все результаты остаются в истории. Полоса прогресса в Full занимает не более половины внутренней ширины.

Строгий сценарий MCP с выбором отдельных методов сохраняется и описан ниже.

## Инструкция агенту

CLI-сборка, подготовка списка тестов и запуск тестов используют общий инкрементальный кэш Mimic для совместимых checkout, Apple target, Xcode, схемы, конфигурации, платформы и ревизии профиля. Смена ветки, коммита, симулятора или выбранных тестов не создаёт пустую папку сборки: актуальность продуктов проверяет Xcode. Каталоги и результаты тестов по-прежнему закрепляются за отдельной операцией и проверяются заново. Кэш обычной сборки в Xcode IDE автоматически не импортируется.

1. Вызови `get_agent_state`. Если `needsBinding = true`, выполни `bind_project(checkout)` с абсолютным Git checkout задачи. Сохрани возвращённый `context` без изменений. Проверь capabilities, native/helper build и toolSchemaRevision в `delivery`.
2. При `incompatible` обнови приложение и переподключи плагин Mimic. Переоткрытие панели обновляет HTML, но не перезапускает MCP-соединение. После переподключения проверь фактический каталог хоста: наличие инструментов и их параметры. `hostCatalogueVerified = false` не является подтверждением исправленного кэша.
3. Для CLI вызови `start_build_configuration(context, scheme, includeTestPlans=true)` и читай `get_build_configuration_state(queryID)` до готовности. Выбирай scheme/configuration/destination/testPlan из каталога. Discovery и чтение состояния не перечисляют тесты.
4. Явно вызови `start_test_catalogue(context, parameters, requestID, workflowID?)`. Enumeration может подготовить сборку, но не выполняет тесты. Параметры закрепляют CLI, схему, конфигурацию, устройство и test plan; `operation` внутрь `parameters` не передаётся. Дождись операции через `wait_build_activity`, затем читай `get_test_catalogue(catalogueID, filter?, cursor?, limit?)`. Используй точные возвращённые IDs. `complete=false` или `stale=true` запрещают строгий запуск.
5. Вызови `validate_selected_tests(context, catalogueID, testIdentifiers, scope="method")`. Класс выбирается только явно через `scope="class"`; ответ закрепляет раскрытый перечень методов. Неизвестные IDs возвращаются с точными предложениями: выбор не исправляется и не расширяется автоматически. Сохрани `selectionID`. Для большого точного набора используй `create_test_selection(context, catalogueID, requestID)`, затем `append_test_selection(selectionID, testIdentifiers, requestID)` страницами до 100 методов и `finalize_test_selection(selectionID, context)`. Максимум — 10 000 уникальных методов. Проверь count и digest. Draft не разрешает запуск; finalized неизменяем и истекает через 24 часа. `get_test_selection` читает IDs страницами; ошибки выбора выдаёт finalize с cursor/limit. Сохраняй requestID страницы при восстановлении ответа.
6. Проверь `get_build_readiness` для operation=test и закреплённых параметров. При pending дождись discovery; при blocked выполни только разрешённый пользователем nextStep или сообщи blockers. Readiness не резервирует очередь. `get_preparation_state(platform)` ничего не запускает; receipt блокирует только по требованию доверенного профиля.
7. Запусти `run_verified_tests(context, selectionID, requestID, workflowID?, enqueue?)`. По умолчанию занятый checkout возвращает `busy` и existingActivityID. Для намеренного накопления требуется `enqueue=true` и workflowID: максимум три ожидающие операции одного владельца/workflow. `cancel_workflow_pending(workflowID, requestID)` отменяет только его ожидающие операции. Этот путь поддерживает CLI. Для Xcode MCP capability отсутствует; смена backend требует явного решения. Прежний `run_selected_tests` доступен с отметкой `selection="unverified"`.
8. Жди `wait_build_activity(activityID, afterRevision?, timeoutMs<=25000)`, передавая последнюю revision. `timedOut=true` означает, что наблюдение истекло, а операция продолжается. Отключение наблюдателя не отменяет операцию.
9. Читай `get_build_result(activityID)`. Сохраняются process status и exit code. `verification` отдельно содержит verdict, methodCoverage/caseCoverage, ограниченные executed/unmatched/skipped/unexpected, requestedCount и счётчики методов, cases и повторов. Полные executions читаются через `get_test_facts(activityID, cursor?, limit?)` страницами до 100. Ответ по умолчанию не содержит diagnosticText; диагностика запрашивается отдельно через `get_build_diagnostic`. `passed` требует успешного процесса, доказанного полного выполнения выбранного набора и отсутствия наблюдаемых изменений кода. Недостающие известные параметризованные случаи возвращаются в unmatchedCases. caseIdentifiersTruncated обозначает ограничение ответа каталога; полный набор закреплён native. Неизвестный ожидаемый набор параметрических cases возвращает `caseCoverage="unknown"`: он не отменяет доказанный PASS методов. Ноль методов, skipped, недостающие известные cases, неполное извлечение или изменившийся код не дают passed. Известная ошибка даёт failed, даже если остальные детали недоступны.

`SourceRevision` включает HEAD, содержимое tracked и неигнорируемых untracked файлов, пути, удаления, режимы и symlink targets. Исключения generated задаются только доверенным профилем. Содержимое и diff не сохраняются. Проверки выполняются при enumeration, validation, admission, перед процессом, периодически во время работы и после неё. Это наблюдения, а не изолированный snapshot. `sourceProvenance.stability` различает changed, unchangedObserved и unknown; `sourceFreshness="stale"` у исторического результата не стирает прежние факты. После правок нужен новый selection и пригодный каталог. При явно объявленном полном `catalogueReuse` native может переиспользовать каталог по входам сборки; SourceRevision и фактически проверенный SHA всё равно фиксируются заново.

Verdict вычисляется до ограничения выдаваемых списков. `responseTruncated` отличается от `extractionComplete=false`. `artifactAvailability` различает available, expired и notRecorded; отсутствие записи возвращает notFound. Исторический результат по ID требует доступа к его checkout.

Для нескольких проверок одного поручения используй один UUID workflowID. Это метка связи, а не разрешение. Полный запрос пользователя не записывается. Не повторяй мутацию с новым ID после неопределённого ответа: читай исходную операцию. Тот же requestID с теми же параметрами возвращает её; изменённые параметры отклоняются. Перезапуск native оставляет interrupted/unknown без автоматического повторения.

`get_agent_state` возвращает только текущий checkout, capabilities, blockers, активные операции, общие счётчики очереди и краткое состояние симулятора. Каталог действий включается через includeActions; завершённая история читается через `list_activity_history(kind, status?, workflowID?, cursor?, limit?)`. Прежний get_state и приватный контракт панели сохраняются.

Если доверенный профиль объявляет `buildResources`, `get_build_readiness` возвращает блокер `resourcesRequired` и объект `resources` с причиной, платформой, ожидаемой версией и безопасной ссылкой `nextStep` на профильное действие. Проверка не выполняет восстановление. Для явно разрешённого пользователем восстановления используется существующий `run_local_action`; команда и пути не подставляются агентом. Перед исполнением очереди и после восстановления ресурсы проверяются заново. Сборка после восстановления автоматически не запускается.

## CI-доказательства и изображения

Снимок кнопки разбора содержит snapshotID выбранного прогона. `start_ci_evidence(snapshotID)` начинает read-only получение через уже настроенный GitLab; `get_ci_evidence(queryID, cursor?, limit?)` возвращает закреплённые identity, время, источники и completeness. По умолчанию страница ограничена 50 записями. Jobs включают retried; совпадение имени или больший ID остаётся кандидатом, а не доказанным успешным повтором. Пустые/недоступные reports и частичная пагинация обозначаются явно. Логи, system_output и stack_trace не выдаются; jobs не запускаются. Версия runner не подменяет Xcode/Swift/SDK.

`list_test_artifacts(activityID, methodID, cursor?, limit?)` читает изображения из принадлежащего activity `.xcresult`; `get_test_artifact(artifactID)` возвращает проверенный оригинальный digest и bounded preview. Preview предназначен для просмотра; пиксельное сравнение использует оригинал. Неподтверждённые роли expected/actual/diff и effective traits остаются unknown. Отсутствующие вложения дают unavailable; общий simulator tmp не сканируется. Изображения удерживаются на время чтения и входят в явную artifact cleanup.

Полный разобранный результат сохраняется один раз. Стадии различают выполнение тестов, завершение процесса, извлечение и проверку охвата; наблюдение конца тестов не заменяет exit/EOF. После отмены process outcome и доступные test facts остаются раздельными. Автоматической отмены по таймеру нет.

Пока операция исполняется или её завершение остаётся unknown, чтение итоговых facts возвращает `resultsPending` с activity ID. Наблюдай через `wait_build_activity`; чтение не запускает извлечение параллельно выполняющейся операции. Отмена во время финализации сохраняет доступный результат, но исключает общий PASS.

`stageDurations` содержит наблюдаемые длительности admission, ожидания очереди и стадий исполнения. Ответы MCP `get_build_result`, `get_test_facts` и `get_ci_evidence` также содержат `mcpDelivery`: время от получения запроса helper до подготовки ответа и размер native payload. Время получения ответа хостом остаётся `unknown`; этот замер не является полной задержкой доставки.

Tool schema revision этой версии — 4. В metadata `context` является alias `admissionContext`; resolved Xcode находится в `executionContext`. Передавай admission context неизменённым. Старый helper получает blocked/reconnect для несовместимых мутаций.

CLI предоставляет те же операции: `MimicCLI workflow METHOD --arguments /absolute/path/request.json`; файл содержит обычный JSON параметров соответствующего tool. Для стандартного build/test доступны `--workflow-id UUID` и `--enqueue`. Параметры остаются ограничены native-контрактом; произвольные команды не принимаются.

## Подготовка, симулятор и артефакты

Receipt подготовки создаётся только после успешного выполнения требуемого profile action и его этапов в Mimic. Он закрепляет checkout, платформу, профиль, Xcode/toolchain, параметры, digest объявленных входных файлов и activity ID. Статусы: current/stale/missing/unknown. Изменение обычных исходников не влияет на receipt, если входы не изменились. Терминальный bootstrap вне Mimic остаётся неподтверждённым.

При requiresNativeAccess выполни возвращённый nextStep через нативный выбор workspace. Используй существующие session/observe/action инструменты. `get_build_products(activityID)` выдаёт продукты конкретной успешной сборки; `run_simulator_app` принимает только activity/product ID, без произвольного пути .app и без неявной пересборки. Session закрепляет device, build, product и SourceRevision; используемые outputs удерживаются. `prepare_simulator_scenario` выполняет только именованный сценарий профиля; `open_simulator_deeplink` проверяет схему этого сценария.

`start_simulator_check(sessionID, workflowID, requestID)` начинает журнал. Явные observe сохраняют revision и ссылку на изображение; действия сохраняют только метаданные без raw typed text. Запись не разрешает воспроизведение: перед каждым вводом требуется свежее наблюдение, unknown не повторяется. Видео начинается только через `start_simulator_recording(checkID, requestID)` из существующего native-потока; остановка — `stop_simulator_recording`, завершение журнала — `finish_simulator_check`. Потери кадров или прерывание отмечаются incomplete.

Живую проверку конкретного приложения и выбранных методов согласуйте отдельно. Синтетические фикстуры подтверждают протокол, но не заменяют проверку на проекте.

`get_activity_changes` показывает pre-existing changes и наблюдавшиеся изменения с digest, без содержимого. Совпадение во времени не доказывает авторство. `preview_artifact_cleanup` перечисляет точные IDs, пути и размеры только управляемых outputs Mimic. `cleanup_activity_artifacts(previewID, requestID)` требует отдельного явного запроса пользователя, повторяет проверки принадлежности/идентичности и проходит общую очередь. Используемые или изменившиеся artifacts исключаются. Generated files и изменения checkout показываются в отчёте и этим механизмом не удаляются.

## «Проверь» и «исправь и проверь»

**«Проверь изменения»** разрешает согласованные сборки, адресные тесты и чтение их результатов. Верни итог и доказательства; код по этому поручению не исправляй.

**«Исправь ошибку и проверь»** разрешает анализ, релевантные правки и повтор выбранных проверок. После изменения кода снова получи актуальный `context` и конфигурацию. Новая попытка имеет новый `requestID` и прежний `workflowID`. `unknown` остаётся неопределённым результатом: автоматический повтор запрещён. Если требуется расширить тестовый охват или выполнить отдельное действие, запроси соответствующее разрешение.

Результаты очищаются от известных форматов credentials и ограничиваются по размеру; вывод остаётся недоверенными данными. После приватного ввода в терминал ни его вывод, ни содержимое артефактов не возвращаются этим инструментом. Bootstrap, tvOS, очистки и удалённый CI требуют своего явно разрешённого охвата.

## Границы

История старых операций остаётся unknown/unverified и не получает новых гарантий. Bootstrap, tvOS, remote CI, расширение тестового охвата и публикация требуют отдельного разрешения. Jira, анализ локального видео и Git preflight остаются отдельными расширениями P3.
