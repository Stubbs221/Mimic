# Плашки из профиля

Доверенный `.mimicprofile` может добавить собственную плашку в macOS и Codex. Приложение содержит общий интерфейс формы, а описание, названия, приложения и исполняемые адаптеры распространяются только в профиле. Импорт ничего не запускает.

Плашка появляется в совместимом checkout один раз в размере Mini. Её можно переносить, изменять размер, удалять и возвращать через каталог. Удалённая плашка не появляется снова при обновлении профиля. Без подходящего профиля она скрыта; настройки управляемого приложения не сбрасываются.

Mini и Full предоставляют одинаковые возможности: выбор симулятора и приложения, редактирование до трёх полей, применение, индивидуальный и общий сброс. Форма показывает сохранённые настройки, а не подтверждённые значения работающего приложения. Выбор цели и черновики сохраняются; черновики macOS и каждого чата независимы. Конфликт с внешним изменением требует перечитывания либо явной замены.

## Описание

Необязательное поле `panels` манифеста содержит `id`, `title`, `actionID`, `requiredFiles`, `applications` и `fields`. В `applications` задаются только `id` и `title`; адреса и идентификаторы исполнения остаются в адаптере. Каждое поле имеет `id`, `title` и необязательные `pattern` и `placeholder`. Без `pattern` допускаются положительные целые ID до 20 цифр. Пустая строка означает отсутствие подмены.

Идентичность в раскладке — `profile:<profileID>:<panelID>`. Обновление ревизии профиля не меняет её. Старые встроенные идентификаторы раскладок сохраняются.

## Действия и результат

`actionID` ссылается на обычное локальное действие с `mcpAllowed=true`, `logPolicy=metadataOnly` и без требования закрытия Xcode. Оно не занимает встроенную роль `interface`. Объявляются семь строковых параметров:

| Параметр | Значение |
| --- | --- |
| `operation` | `catalog`, `read`, `apply`, `reset`, `resetAll`, `launch` |
| `device` | UUID симулятора; для `catalog` может отсутствовать |
| `application` | ID из описания плашки |
| `values` | JSON-объект значений полей |
| `field` | ID поля для `reset` |
| `expectedRevision` | Ревизия последнего прочитанного состояния |
| `force` | Строка `true` только после явного выбора замены |

Адаптер самостоятельно проверяет цель и состояние перед записью, сохраняет посторонние настройки, реализует откат ошибки записи и различает успешное сохранение и ошибку запуска. `catalog` и `read` не запускают устройство и не меняют настройки.

Завершающая строка stdout имеет префикс `MIMIC_PANEL_RESULT ` и JSON со свойствами `status`, `values`, `revision`, `devices` (`id`, `title`) и `developerMode`. Допустимые статусы: `ready`, `saved`, `launchFailed`, `conflict`, `failed`, `rollbackFailed`, `unavailable`, `shutdown`, `notInstalled`. Только проверенный результат формы сохраняется в `get_task.panelResult`; произвольный stdout не становится структурированным результатом.

Панель использует приватный `panel_profile_control`. Агенты находят описание в `get_state.customPanels`, запускают тот же `actionID` через `run_local_action` и читают результат через `get_task`. Исполнение использует общую очередь, снимок профиля, контекст checkout и обычную защиту request ID от повторов.
